# VR Task Project

VR-проект на Unity с системой взаимодействия с объектами и последовательного выполнения задач.

## 🎯 Основная механика

Игрок выполняет действия в VR в соответствии с поставленными задачами.

Система проверяет действия игрока и предоставляет визуальную обратную связь:

- 🟢 **Правильное действие** — соответствующая задача окрашивается в зелёный цвет.
- 🔴 **Неправильное действие** — соответствующая задача окрашивается в красный цвет.

После выполнения необходимых действий игрок может перейти к следующему этапу.

## 🏗 Архитектура

В проекте используются принципы **SOLID** и **Clean Dependency Injection**.

Основной упор сделан на то, чтобы компоненты имели минимальную связанность и отвечали только за свою ответственность.

### Используемые принципы

- **SRP** — каждый компонент отвечает за свою задачу.
- **DIP** — зависимости строятся через абстракции.
- **Dependency Injection** — зависимости передаются извне, а не создаются внутри компонентов.
- **Interfaces** — используются для определения контрактов между системами.
- **Events / Delegates** — используются для передачи событий между независимыми компонентами.

## 💉 Dependency Injection

Для связывания зависимостей используется отдельный слой **Installer / Binder**.

Это позволяет:

- уменьшить жёсткую связанность компонентов;
- не использовать `FindObjectOfType` для получения зависимостей;
- не создавать зависимости непосредственно внутри классов;
- упростить замену реализаций;
- сохранить игровую логику независимой от UI и других систем.

## 🧩 Код

Стиль кода — **базовый и практичный**.

Основной принцип разработки:

> Простота важнее избыточной архитектуры.

Я старался использовать **как можно меньше скриптов**, при этом сохраняя разделение ответственности и соблюдая основные принципы SOLID.

В проекте намеренно не используются дополнительные паттерны и абстракции там, где они не дают практической пользы.

Основной упор:

- простота;
- читаемость;
- понятные зависимости;
- небольшие классы;
- удобство поддержки;
- отсутствие лишней сложности.
